# افزودن سرور دیگر

داشبورد روی یک ماشین نصب می‌شود، ولی می‌تواند 9router‌های ماشین‌های دیگر را هم با همان نمودارها نشان دهد. روی هر ماشین دیگر فقط یک **agent** کوچک و فقط‌خواندنی لازم است. داشبورد از آن درخواست‌ها را می‌کشد.

```
ماشین اصلی                          ماشین دیگر
┌──────────────┐   HTTP + توکن    ┌──────────────────────┐
│ داشبورد :9010 │ ───────────────► │ agent :9011           │
└──────────────┘                   │  /sources/<name> (فقط خواندنی)
                                   └──────────────────────┘
```

- agent فقط فایل `data.sqlite` را با `readonly` می‌خواند. به docker socket یا خود 9router دسترسی ندارد.
- هر درخواست agent باید هدر `Authorization: Bearer <AGENT_TOKEN>` داشته باشد.
- 9router‌های آن سرور در داشبورد با نام `<نام سرور>/<نام 9router>` ظاهر می‌شوند (مثلاً `office/sales`) و در همه‌ی نمودارها، گزارش‌ها و زمان‌بندی‌ها مثل منبع‌های محلی کار می‌کنند.

## ۱. نصب agent روی ماشین دیگر

کد پروژه را روی آن ماشین کپی کنید (مثلاً در `/opt/prompt-dashboard-agent`) و یک `.env` بسازید:

```bash
cd /opt/prompt-dashboard-agent
echo "AGENT_TOKEN=$(openssl rand -hex 24)" > .env
cat .env
```

در `docker-compose.agent.yml` زیر `volumes` برای هر 9router یک خط بگذارید:

```yaml
      - /opt/9router-sales/data/db:/sources/sales
      - /opt/9router-support/data/db:/sources/support
```

بعد:

```bash
docker compose -f docker-compose.agent.yml up -d --build
curl -s localhost:9011/healthz
```

> توکن را جایی نگه دارید؛ در مرحله‌ی بعد لازم است. پورت 9011 باید از ماشین داشبورد قابل دسترس باشد. اگر فایروال دارید، فقط نشانی ماشین داشبورد را به این پورت اجازه بدهید.

## ۲. اضافه کردن در داشبورد

«تنظیمات ← سرورهای دیگر ← افزودن سرور»:

| فیلد | توضیح |
|---|---|
| نام کوتاه | حروف انگلیسی و عدد، مثل `office`. پیشوند منبع‌ها می‌شود و بعداً عوض نمی‌شود |
| نام نمایشی | اختیاری، مثل «دفتر مرکزی» |
| نشانی agent | مثل `http://192.168.1.100:9011` |
| توکن | همان `AGENT_TOKEN` (دست‌کم ۱۶ نویسه) |

با «آزمایش اتصال» می‌توانید قبل از ذخیره مطمئن شوید که agent در دسترس است و ببینید چه 9router‌هایی دارد. بعد از «افزودن»، منبع‌ها خودکار ساخته و همگام‌سازی‌شان شروع می‌شود. زمان‌بندی‌هایی که «همه‌ی منبع‌ها» را انتخاب کرده‌اند آن‌ها را هم شامل می‌شوند.

توکن فقط نوشتنی است: پس از ذخیره در هیچ‌جای رابط نمایش داده نمی‌شود. برای عوض کردن آن، agent را با توکن جدید بالا بیاورید و در داشبورد دوباره سرور را اضافه کنید یا با API (`PATCH /api/servers/:id`) توکن را به‌روز کنید.

## اضافه شدن 9router تازه روی همان سرور

یک خط volume به `docker-compose.agent.yml` اضافه کنید و `docker compose -f docker-compose.agent.yml up -d` بزنید. در داشبورد دکمه‌ی «بررسی دوباره» کنار سرور را بزنید (یا منتظر اجرای بعدی زمان‌بندی بمانید؛ پیش از هر اجرا منبع‌های جدید خودکار پیدا می‌شوند).

## حذف سرور

حذف سرور در داشبورد، همه‌ی منبع‌ها، کاربران، گفتگوها و درخواست‌های ذخیره‌شده از آن سرور را برای همیشه پاک می‌کند. اگر فقط می‌خواهید همگام‌سازی متوقف شود، آن را **غیرفعال** کنید؛ داده‌ها می‌مانند.

## عیب‌یابی

| پیام | معنی |
|---|---|
| agent در دسترس نیست | نشانی/پورت اشتباه است، agent بالا نیست یا فایروال جلوی آن را گرفته. از ماشین داشبورد امتحان کنید: `curl http://<ip>:9011/healthz` |
| agent توکن را نپذیرفت | `AGENT_TOKEN` آن سرور با توکن واردشده یکی نیست |
| منبعی نمی‌آید | داخل agent بررسی کنید: `docker compose -f docker-compose.agent.yml exec agent ls /sources/<name>` باید `data.sqlite` را نشان دهد |
| سرور خاموش است | آخرین خطا در کارت سرور و کارت هر منبع دیده می‌شود. وقتی agent دوباره بالا بیاید، همگام‌سازی بعدی خودکار ادامه می‌دهد و چون هم‌پوشانی ۱۵ دقیقه‌ای دارد چیزی از دست نمی‌رود، مگر آنکه 9router خودش رکوردها را چرخانده باشد (هشدار «شکاف داده») |

## نکته‌ی امنیتی

ارتباط agent با داشبورد HTTP ساده است. اگر دو ماشین روی شبکه‌ی داخلی‌اند مشکلی نیست؛ روی اینترنت آن را پشت یک reverse proxy با HTTPS بگذارید یا با VPN/تونل وصل کنید.
