# راهنمای نگهداری

## همگام‌سازی (Scheduler)
- **کار هر زمان‌بندی:** تعیین می‌کند کدام منبع‌ها خوانده شوند و با چه دوره‌ای:
  - «هر N دقیقه»، یا
  - یک عبارت cron.

  همه‌ی زمان‌ها به وقت تهران است.
- **پنجره‌ی فعال اختیاری:** می‌توان آن را به روزهای هفته و ساعت محدود کرد، مثلاً «روزهای کاری ۸ تا ۲۰».
- **هم‌پوشانی:** هر sync ردیف‌هایی را می‌خواند که از ۱۵ دقیقه قبل از آخرین cursor به بعد هستند. رکوردهایی که 9router بعداً به‌روز کرده هم این‌طوری گرفته می‌شوند. ردیف‌ها با id خودشان upsert می‌شوند، پس تکرار ایجاد نمی‌شود.
- **قفل هر منبع:** جلوی دو sync هم‌زمان روی یک منبع را می‌گیرد.
- **تاریخچه‌ی اجراها:** در صفحه‌ی زمان‌بندی دیده می‌شود.

### شکاف داده
9router فقط تعداد محدودی رکورد آخر را نگه می‌دارد. اگر قدیمی‌ترین رکورد منبع جدیدتر از آخرین cursor ما باشد، یعنی بخشی از داده قبل از sync پاک شده است. این حالت در کارت منبع با هشدار «شکاف داده» دیده می‌شود.

**راه‌حل:** دوره‌ی زمان‌بندی را کوتاه‌تر کنید.

### نحوه‌ی ذخیره
- **بدون کوتاه کردن:** هر پیام، جواب، reminder و خروجی ابزار، با هر اندازه‌ای، کامل ذخیره می‌شود. صفحه فقط پیش‌نمایش می‌گیرد و متن کامل را با «نمایش متن کامل» می‌آورد.
- **هر متن یک بار:** متن پیام‌ها در جدول `texts` با hash محتوا نگه داشته می‌شود. reminderها، CLAUDE.md و خروجی ابزاری که در چند گفتگو یا subagent تکرار شده یک بار جا می‌گیرد.
- **فشرده‌سازی:** متن‌های بالای حدود ۱۲۸ بایت با lz4 فشرده می‌شوند.
- **پاک‌سازی متن‌ها:** متنی که دیگر هیچ پیامی به آن اشاره نمی‌کند در پاک‌سازی شبانه حذف می‌شود.

### رکوردهای ناقص
9router رکوردهای خیلی بزرگ را کوتاه ذخیره می‌کند. این رکوردها با برچسب «ناقص در منبع» و فقط با پیش‌نمایش ذخیره می‌شوند. متن کامل آن‌ها در خود 9router هم موجود نیست.

## نگهداری داده (Retention)
- **پیش‌فرض:** همه‌چیز نگه داشته می‌شود.
- **محدود کردن:** در «تنظیمات ← نگهداری داده» تعداد روز را تعیین کنید. هر منبع می‌تواند مقدار جداگانه داشته باشد.
- **زمان اجرا:** پاک‌سازی هر شب ساعت ۳ بامداد تهران اجرا می‌شود. دکمه‌ی «اجرای پاک‌سازی همین الان» هم وجود دارد.

## کاربران
9router کلید API یا نام کاربر را ذخیره نمی‌کند. هویت کاربر به این ترتیب استنتاج می‌شود:
1. شناسه‌ی account/device در `metadata.user_id` که Claude Code می‌فرستد.
2. مسیر home داخل prompt، مثل `C:\Users\<name>`.

اگر یک نفر با دو شناسه دیده شد، در تنظیمات آن‌ها را **ادغام** کنید. می‌توانید برای هر کاربر **نام نمایشی** هم بگذارید.

## بکاپ و بازیابی

```bash
cd /opt/prompt-dashboard
docker compose exec -T db pg_dump -U prompt -Fc prompt > backup-$(date +%F).dump
```

```bash
docker compose exec -T db pg_restore -U prompt -d prompt --clean < backup-YYYY-MM-DD.dump
```

## به‌روزرسانی

```bash
cd /opt/prompt-dashboard
# کد جدید را کپی کنید (.env و pgdata دست نخورند)
docker compose up -d --build
```

schema در شروع اپ به‌صورت idempotent اعمال می‌شود.

## عیب‌یابی

| مشکل | راه‌حل |
|---|---|
| رمز فراموش شده | در `.env` یک `ADMIN_PASSWORD` جدید بگذارید و `RESET_ADMIN_PASSWORD=true` کنید. بعد `docker compose up -d` را اجرا کنید و پس از ورود دوباره آن را `false` کنید |
| منبعی دیده نمی‌شود | mount در `docker-compose.yml` را چک کنید. داخل پوشه باید `data.sqlite` باشد: `docker compose exec app find /sources -name data.sqlite`. پوشه‌های `_*`، `backups`، `logs` و `mitm` جستجو نمی‌شوند |
| sync خطا می‌دهد | پیام خطا در کارت منبع و جدول اجراها آمده. لاگ کامل: `docker compose logs app --tail 200` |
| دیسک پر شده | دوره‌ی نگهداری را کم کنید و پاک‌سازی را اجرا کنید. حجم دیتابیس در تنظیمات دیده می‌شود |
| «متن این درخواست بزرگ‌تر از حد ذخیره‌ی 9router بود» | خود 9router متن را نگه نداشته است. سقف پیش‌فرضش (`observabilityMaxJsonSize`) فقط ۵ KB است و هر درخواست Claude Code بین ۷۰ تا ۲۰۰ KB است. قانون این است که همه‌ی 9routerها روی ۲۰۴۸۰ (۲۰ MB) باشند: کاربرهای تازه آن را از `_template/.env.example` و `add-user.sh` در `/opt/9router-users` می‌گیرند، و برای 9routerهای موجود مقدار ذخیره‌شده در تنظیمات خود 9router تعیین‌کننده است. درخواست‌هایی که قبلاً بریده شده‌اند برنمی‌گردند |
| سلامت سرویس | `curl -s localhost:9010/healthz` |
| سرور دیگر وصل نمی‌شود | [docs/servers.md](servers.md) را ببینید |
